## 1. サイト名とデザインコンセプト

### サイト名: PLAYCE（プレイス）

**play + place** の混成語で「遊べる場所」。IDERIA（イデアル＋イストリア）と同じ造語の作り方で、姉妹サイトとして並ぶ。

- 表示名は **PLAYCE**。副題として「ゲーム制作・プログラミング学習アーカイブ」を併記し、何のサイトかは副題で伝える。
- **URL（`/game-learning-archive/`）は変更しない。** 既存リンク・学会資料に記載したURLが切れるため、変えるのは表示名だけ。
- 旧名「ゲーム制作・プログラミング学習アーカイブ」は19文字あり、ヘッダーでは「学習アーカイブ」に切り詰めて表示していた。**名前として機能していなかった**のが変更の理由。

### 世界観: 作品が主役。演出は脇役

配色は深い青緑（深海を思わせるダークトーン）を引き継ぐが、**深海の比喩を前面に出す演出はやめる**。

**やめたもの（v3.0）**: 深度メーター（HUD）、右側の深度レール、気泡アニメーション、背景の巨大な深度数字、「潜行開始」「ランダムに1本潜る」「浮上する」「第1層／最深部」などの潜水用語。

理由: 装飾が5系統同時に動いていて、**肝心の作品より装飾が目立っていた**。スマホではヘッダー＋深度バー＋層ボタンで固定要素が3段になり、さらに「浮上する」ボタンが本文に重なっていた。

**残すもの**: 深い青緑の配色、セクションを順に下っていく縦構成（あそぶ→よむ→しくみをしる→つくる→きろく）、`prefers-reduced-motion` 対応。セクションは「第N層」ではなく**普通の見出し**として扱う。

### 1-3. 用語

- **「作品一覧」という語は使わない**（安っぽく見えるため）。作品の一覧は「**作品一覧**」、通し番号は「**作品No.**」と呼ぶ。ナビの項目名も「作品」。
- 実績バッジの文言も「作品一覧に記録した」ではなく「見た」に統一する。

### 1-4. 見た目の原則（v3.0で明文化）

1. **カードに出す情報は絞る。** カードのタグは「ジャンル」と「年度」だけ。技術タグ（Python / pygame など）は**34作品中27作品（79%）に付いていて区別に寄与しない**のに面積を取るため、カードには出さず作品詳細ページに置く。
2. **サムネイルは見た目を揃える。** 同じ比率（16:10）・暗い下地・細い枠線で統一する。画像が無い作品（34件中10件）は、絵文字ではなく**作品名を使ったプレースホルダ**にする。
3. **アクセント色は1色（ミント）に絞る。** ジャンル・年度のチップは色分けせず、地味な枠線＋文字色にする。色数を増やさない。
4. **画面に固定するものは1つまで。** ヘッダーのみ。ページ内の移動手段はヘッダーのメニューに集約する。
5. カードの高さを揃える（説明文は2行で省略）。

### 1-1. 演出の強度（v2.2で明文化）

初版の実装は装飾が控えめすぎて「深海」が伝わらなかったため、次の強度を最低ラインとする。いずれも `prefers-reduced-motion` で停止・非表示にすること。

- **泡**: 海面だけでなく各層にも配置し、実機で視認できる不透明度にする（目安 0.35〜0.7）。層が深いほど数を減らし、ゆっくり昇らせる。
- **深度のウォーターマーク**: 各層の見出し脇に、深度の数字を大きく（clamp 56〜120px相当）薄く敷く。深度・数値表示は**等幅書体**（システム等幅）で統一する。
- **層境界**: 層の切り替わりに目盛り（ティック）付きの境界線を置き、潜っている実感を出す。
- **ビネット**: 深い層ほど画面周辺を暗く落とす。
- 作品カードは「発見済み」で見た目が変わること（既定）。加えて**未発見をシルエット表示にする任意設定**を用意する（3-6）。

## 3-1. 作品一覧の並べ方（v3.1）

`/games/` は**全作品を1つの並びで出さない**。「どの実施で何が生まれたか」が分かることを優先し、**実施プロジェクト（`activities` の1件）ごとのまとまり**にする。

- 並び順は**新しいプロジェクトから**。年の無いもの（IDERIAの制作物など）は最後にまとめる。
- 各プロジェクトの見出しには、**活動名／年度／種別／場所／作品数／概要／活動詳細へのリンク**を出す。
- **1作品が複数のプロジェクトに属する場合は、その全部に出す。** 例: 第3回ゲームジャムの作品が OneButtonGames にも収録されている。
  - このため、カードの総数（45枚）と作品数（34件）は一致しない。**件数表示は作品数（重複を除いた数）で数える。**
  - `site.js` の絞り込みは `id → 要素の配列` で持ち、同じ作品のカードをまとめて出し入れする。
- 絞り込みで**中身が全部消えたプロジェクトは、見出しごと隠す。**
- ページ冒頭に「**プロジェクトから探す**」（各プロジェクトへのアンカーと作品数）を置く。
- 検索・絞り込み・並び替え・URL反映は従来どおり動くこと。並び替えは各プロジェクトの中で効く。

## 3-9. 操作デバイスの表示（v3.3）

訪問者の多くはスマートフォンで見る。一方、遊べる23作品のうち21作品はキーボードを使う。
**開く前にキーボードの要否が分かる**よう、作品カードのチップ列に操作デバイスを出す。

- 判定は各作品の `controls`（操作方法の文章）**だけ**を根拠にする。推測で足さない。
  - キーボード: `キー` `Enter` `スペース` `矢印` `ESC` のいずれかを含む
  - マウス: `クリック` `マウス` のいずれかを含む
  - `ダブルタップ`（キーの連打を指す作品がある）は指の操作として数えない。
- チップは「**キーボードが要るか**」の一問だけに答える。両方使う作品も `⌨ キーボード` と出す。
- 内訳（両方使う／マウスだけ）は作品詳細の「操作方法」の注記とプレイページ冒頭で説明する。
- タッチ操作で遊べるかは未検証のため、**「タッチ対応」とは書かない**。
## 2. 層構造（トップページの再構成）

トップページは **あそぶ → よむ → しくみをしる → つくる → きろく** の順に並べる。（v3.0で「潜行ルート」の呼び方と深度HUD・層ジャンプの固定ナビは廃止した。下表の「深度表示の目安」は当時の記録として残す。）

| 層 | 名前 | 内容 | 深度表示の目安 |
|---|---|---|---|
| 海面 | ようこそ | ヒーロー。サイト名・キャッチコピー・「作品を見る」ボタン | 0m |
| 第1層 | あそぶ | ブラウザで遊べるゲームのハイライト（作品カード数枚＋「作品一覧をひらく」） | 100m |
| 第2層 | よむ | ソースコード閲覧の紹介（コード画面のプレビュー＋対応作品数） | 300m |
| 第3層 | しくみをしる | 学習ページ（逆引きコード）の紹介。基礎/入門/応用の3段階 | 600m |
| 第4層 | つくる | 自分で作ってWeb化するまでの道のり（README/学習ページへの誘導） | 1000m |
| 最深部 | きろく | 活動アーカイブ（ゲームジャム・高大連携・年表）への入口 | 2000m |

- 各層に「この層でできること」の短いフレーバーテキストを置く（例: 第1層「まずは触れてみよう。すべてのゲームはブラウザで動く」）。
- 深度の数字は当時の演出用で、実データではない。v3.0で画面からは削除済み。

## 3. 遊び要素

1. **深度メーター**: 画面端（PCは右端、スマホは上部細帯）に現在のスクロール位置を「深度◯◯m」として常時表示。層に入ると層名も出る。
2. **発見スタンプ**: ゲーム詳細/プレイページを開いた作品に「発見済み」スタンプが付く。ゲーム一覧（作品一覧）でスタンプ数「◯◯/34 発見」を表示。保存は `localStorage`（try/catchで包み、無効環境では単に表示しない）。
3. **実績バッジ**: 「はじめての潜行（初回訪問）」「はじめての発見（初プレイ）」「5作品発見」「10作品発見」「コードを読んだ」「全層到達（最深部までスクロール）」程度。達成時に控えめなトースト表示。localStorage保存。サーバー送信はしない。
4. **「ランダムに1本潜る」ボタン**: 作品一覧とトップに設置。プレイ可能な作品からランダムに1つ選んでプレイページへ。
5. **浮上ボタン**: 「上に戻る」を「浮上する」と表記し、泡の演出付きで最上部へ。
6. **未発見シルエット表示（任意・既定オフ）**: 作品一覧で未発見作品のサムネイルを伏せる表示を切りかえられる。既定はオフ（初見の閲覧性を損なわないため）。設定は localStorage に保存。
7. **発見率の可視化**: 作品一覧の「探検記録」に発見数のプログレスバーを置く。
8. **記録のリセット**: 作品一覧（および About からの導線）に「発見記録・実績を消す」ボタンを置き、確認のうえ localStorage の記録を削除できるようにする。トーストは**1件ずつ順に表示**し、同時に積み上げない。

## 4. 便利機能

1. **作品一覧の強化**: 既存のフィルタ（活動・年度・カテゴリ・検索）を維持したまま、(a) プレイ可能のみ表示トグル (b) 並び替え（名前順・活動順） (c) 作品No.表示（データの並び順で自動採番）を追加。
2. **層ジャンプ目次**: 全ページ共通ヘッダーに「作品一覧・活動・学習・About」への直リンク。トップでは層ジャンプ（海面〜最深部）も。
3. **キーボードショートカット**: `/` で作品一覧の検索欄へフォーカス。Escで解除。それ以上は増やさない。
4. **共有**: 作品詳細ページに「URLをコピー」ボタン。
5. **パンくず**: 既存構造を維持。
6. **関連サイト**: 全ページ共通で、**フッターのすぐ上**に「関連サイト」セクションを置く。**サイト名＋1行紹介のカード形式**で、外部リンクとわかる表示にする（別タブで開く・`rel="noopener"`・カードにURLを併記）。掲載は下表の2件。URLは `site/src/data/site.json` から読み、**空欄のカードは表示しない**（2件とも空ならセクションごと非表示）という既存の方式を守る。フッター内の同じ外部リンク枠は引き続き併置してよい。

| サイト名 | URL（site.json のキー） | 1行紹介 |
|---|---|---|
| 永野斗遠 ポートフォリオ | `portfolioUrl` = `https://109mei.github.io/` | このアーカイブの制作者の業績・活動 |
| IDERIA公式サイト | `ideriaOfficialUrl` = `https://109mei.github.io/ideria-official/` | ゲームを生み出している制作団体 |

7. **絞り込み条件のURL反映**: 作品一覧の検索語・絞り込み・並び替え・表示状態をクエリ文字列に反映し、リンク共有・ブックマーク・再読み込みで復元できるようにする（`history.replaceState`。履歴を汚さない）。
8. **検索対象の拡張**: タイトル・説明・ジャンルに加え、制作元・関連活動名・使用技術・活動種別も検索対象にする。並び替えの「名前順」は辞書順であることをラベルで明示する（データに読みを持たないため）。
9. **前後ナビ**: 作品詳細に作品No.順の「前の作品／次の作品」、学習トピックに番号順の前後リンクとパンくずを置く。
10. **発見状態フィルタ**: 作品一覧に「未発見のみ／発見済みのみ」の絞り込みを追加（記録が使えない環境では出さない）。
11. **モバイル最適化**: 作品一覧の絞り込みは「絞り込み」ボタンで開閉する（既定は閉、検索欄だけ常時表示）。ソース閲覧ページのファイル一覧は横スクロールの1行に収め、素材ファイルは折りたたむ。キーボード操作のヒントはポインタ環境のみ表示。
12. **共有・検索エンジン対応**: 各ページに OGP（`og:title`/`og:description`/`og:url`/`og:image`）と `twitter:card` を出力する。作品ページはサムネイルを、その他は既定画像を使う。`sitemap.xml` と `robots.txt` も生成する（いずれも `siteUrl` 未設定なら出力しない）。
13. **最終ビルド日**: フッターに「最終更新（ビルド）日」を表示する。データに追加日を持たないため、更新の目安として生成日を出す。
15. **実績トーストの位置（v3.3）**: 本文に重ねない。**スマホは画面上部（ヘッダーの直下）**、**PCは右下**に出す。表示は約3.8秒（連続時は2秒）で自動的に消える。「上へ戻る」ボタンとは重ならない位置にする。
16. **連絡手段（v3.3）**: About の「掲載内容に問題がある場合」の案内から、`site.json` の `repoUrl` をもとに **GitHub Issues** へリンクする。連絡手段を書くなら到達先を必ず用意する。
14. **実績棚の再掲**: About にも実績バッジの一覧を表示する（獲得状況は localStorage から反映）。
